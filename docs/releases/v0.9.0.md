# 发布说明 v0.9.0（适配 dsh 0.2.1-rc.2）

[← 返回 README](../README.zh.md) ｜ 相关：[适配记录](../design/adaptation-dsh-0.2.1-rc.2.md) ·
[v0.8.2 发布说明](v0.8.2.md) ·
[dsh 0.2.0-rc.2 适配记录](../design/adaptation-dsh-0.2.0-rc.2.md)

**发布日期**：2026-10-17 ｜ **区间**：`v0.8.2 → v0.9.0`
**宿主**：dsh `0.2` 线，从 `0.2.1-rc.2` 起。dsh 0.2.0 继续使用插件 v0.8.2。
dsh 0.1.5 继续使用插件 v0.6.0。

官方 dsh 仍不发现项目级 MCP 文件、不按会话隔离工具、也没有 MCP 专用 CLI。
v0.9.0 把装载后端对齐到宿主自带的 `@deepseek-ai/dsh-mcp-client@0.2.1-rc.2`。
这一版 client 的桥接代码与 0.2.0-rc.2 相同，配置字段没有新增。

源码版本和 Git 标签不表示 `dsh-project-mcp-manager` 或 `dsh-project-mcp-ui`
已经发布到 npm。

---

## 亮点速览

| 主题 | 一句话 |
|---|---|
| 依赖下限 | `@deepseek-ai/dsh-mcp-client` 与 UI 的 `dsh-native-command` 抬到 `^0.2.1-rc.2`；cordis 开发依赖 `^4.0.5` |
| 宿主门禁 | 两包 `engines.dsh` 为 `^0.2.1-rc.2` |
| 项目焦点 | 仍读 `session.header.cwd`。`working_directory` 不挪 MCP 可见性 |
| 传输 | 仍是 `stdio` \| `streamable-http`。装载时的 MCP SDK 为 2.2.0 |

---

## 用户可见变化

- 支持矩阵改为 **dsh ≥ 0.2.1-rc.2**（`0.2` 线，`engines.dsh` 上限 `<0.3.0-0`）。
  `^0.2.0-rc.2` 解析不到 `0.2.1-rc.*`，且旧 client 的 cordis peer `~4.0.4`
  接不住宿主的 4.0.5。
- 在 dsh 0.2.1 里调用 `working_directory` 只改当前执行目录。项目 MCP 仍跟着
  会话创建时的原始项目。
- 设置页仍挂在「设置 → 内置插件 → 插件：MCP 管理」。精确 Fetch 路由由宿主
  只对 owner Peer 放行，页面本身的注册方式不变。
